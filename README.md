# ChargeOps Pilot — سامانه پایش عملیات شارژینگ (پایلوت آزمایشی)

**نسخه:** 0.1.0 (MVP)  
**محیط اجرا:** Next.js 16+ App Router (TypeScript) + Supabase PostgreSQL  
**سیاست داده:** کاملاً ساختگی (Synthetic Data Only) — بدون اتصال به شبکه یا سامانه‌های واقعی  

---

> ### ⚠️ هشدار و مرز ایمنی (Safety Boundary)
> **«دموی داده‌های مصنوعی؛ بدون اتصال به شبکه یا سامانه واقعی»**  
> این سامانه یک محصول رسمی شرکت ایرانسل نیست، به هیچ یک از زیرساخت‌ها، سوئیچ‌ها، پایگاه‌داده‌ها یا شبکه‌های عملیاتی متصل نبوده و هیچ‌گونه اقدام عملیاتی (مانند بازنشانی، شارژ مجدد، تغییر کانفیگ یا اجرای دستورات شبکه) انجام نمی‌دهد. تمامی رویدادها و مستندات این پروژه کاملاً ساختگی و فرضی هستند.

---

## ۱. اهداف و قابلیت‌های سامانه

1. **داشبورد شاخص‌ها (Dashboard):** محاسبه قطعی و دترمینستیک متریک‌های کلیدی شارژینگ (تعداد کل تراکنش‌ها، تراکنش‌های موفق/ناموفق، نرخ موفقیت، روند خطاها و خطاهای پرتکرار) بر پایه پایگاه‌داده بدون استفاده از محاسبات تخمینی LLM.
2. **پایگاه دانش عملیاتی (Operational Runbooks):** بازیابی لغوی و دقیق کدهای خطا و جستجوی تمام‌متن (Full-Text Search) در ران‌بوک‌های ساختگی معتبر و فعال.
3. **دستیار هوشمند امن (Safe Assistant):** مسیریابی در چهار مسیر مشخص (Analytics, Knowledge, Combined, Unsupported)، ارائه استناد دقیق به مستندات با شناسه، نگارش و بخش، و امتناع صریح در موارد کمبود شواهد.
4. **امنیت و کنترل دسترسی (Security & RBAC):** احراز هویت مبتنی بر دعوت (Invitation-only)، سطوح دسترسی `viewer` و `admin`، محافظت در مسیرهای سرور و استفاده از Row Level Security (RLS) در پایگاه‌داده.

## ۳. راه‌اندازی و اجرای محلی

### گام ۱: دریافت کدها و ورود به دایرکتوری
```bash
git clone https://github.com/ali7887/ChargeOps-Pilot.git
cd ChargeOps-Pilot
```

### گام ۲: نصب وابستگی‌ها
```bash
npm install
```

### گام ۳: تنظیم متغیرهای محیطی
یک فایل `.env.local` بر اساس الگوی `.env.example` بسازید:
```bash
cp .env.example .env.local
```
مقادیر مورد نیاز:
```env
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=your-supabase-publishable-key
SUPABASE_SERVICE_ROLE_KEY=your-supabase-service-role-key
AI_PROVIDER=none
DEMO_DATA_ONLY=true
```
*(در حالت اولیه، نیازی به کلید API هوش مصنوعی نیست و سامانه در حالت `AI_PROVIDER=none` با قالب‌های دترمینستیک کار می‌کند).*

### گام ۴: اجرای دستورات بررسی و تست
```bash
# بررسی انواع داده (Typecheck)
npm run typecheck

# بررسی استانداردهای کدنویسی (Lint)
npm run lint

# اجرای تست‌های واحد و مرجع
npm test

# بیلد نهایی برنامه
npm run build
```

### گام ۵: اجرای برنامه در محیط توسعه
```bash
npm run dev
```
برنامه در آدرس `http://localhost:3000` در دسترس خواهد بود.

## ۵. محدودیت‌های شناخته‌شده و سلب مسئولیت

- تمامی داده‌ها، کدهای خطا، نام سرویس‌ها و ران‌بوک‌های موجود در این مخزن ساختگی هستند.
- در نسخه ۱، بازیابی دانش به‌صورت Lexical / Full-Text است و نباید به عنوان Semantic RAG معرفی شود.
- عملیات شبکه یا تعامل عملیاتی با سامانه‌ها کاملاً مسدود و غیرفعال است (Read-Only).
