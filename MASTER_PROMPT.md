### Provisional metric definition

Until reviewed by a domain SME, use this explicit provisional definition for the demo:

- Time window is `[from,to)` in UTC.
- The metric is based on transaction inception/start time.
- Include events received by the `as-of` timestamp.
- Deduplicate by unique `event_id`.
- Determine each transaction's canonical state at the `as-of` time using a deterministic, documented rule based on the latest reliable event. Define and test tie-breaking and late-arrival behavior; never rely on row order.
- Canonical states: `success`, `failed`, `reversed`, `pending`.
- Success rate = number of canonical `success` transactions divided by canonical `success + failed` transactions.
- `reversed` and `pending` are reported separately and excluded from the denominator.
- If the denominator is zero, return `N/A`, not 0%.
- Use `attempt_id` only for separately labelled attempt-level metrics.

Every metric answer must state its definition, UTC time window, `as-of` timestamp, and relevant data limitations. This is a demo design assumption, **not a claim about Irancell's operational definitions**. A domain SME must approve or replace it before any real-world use.

- Pending state.

- Time-zone normalization and daylight-saving conversion.

- Zero denominator.
